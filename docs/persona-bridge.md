# Local persona bridge

Set `JEV_PERSONA_MODE=1`, `JEV_PERSONA_TOKEN` to a random secret of at least 32 characters, `JEV_PERSONA_PORT=8766`, and explicit comma-separated `JEV_PERSONA_ITEMS` / `JEV_PERSONA_PLAYERS` allowlists. Use the same credential in NetTyan. The listener binds only 127.0.0.1, rejects browser Origin requests, requires `Authorization: Bearer TOKEN`, caps bodies at 32 KiB, and accepts JSON. Keep credentials out of commits and logs.

- GET `/snapshot`: current session/observation UUID, Unix timestamp, connected/health/food/dimension/version/position, allowed registry items, visible players, inventory counts, world_id and active_goal_id. Ground/feet/head block names and biome come from three direct loaded block reads; absent chunks return null. nearby_entities lists at most twelve closest loaded entities within 24 blocks (name, type, distance, health only when known). This is nearby server state, not a line-of-sight or camera claim; no terrain scan is performed.
- GET `/events?after=N`: `{events, cursor, oldest_sequence, has_more}`. Responses are capped at 64 KiB of serialized UTF-8 JSON; cursor is the last returned event sequence (or the requested cursor when empty). Fetch the next page with that cursor while has_more is true. Sequence is per connection. Reset the client cursor when session_id changes. A bounded 1,000-event ring is not durable delivery; oldest_sequence identifies missing history. Chat events have type `chat`, user and msg. Goal events have goal_id, status, verified and summary. All events carry event_id, session_id, sequence and observed_at.
- POST `/goal`: schema_version=1, UUID goal_id, persona_id, session_id, observation_id, issued_at, expires_at, state=`proposed`, spec. Exactly `{kind:"obtain"|"craft",item,count,deliver:false}` or `{kind:"follow"|"come",target}`. These select generic upstream tactical capabilities, not predefined scenarios. Unknown fields are rejected. Reply status accepted/rejected and stable reason on rejection. Same accepted ID/content returns its original acknowledgement; changed content conflicts. Acceptance is not completion.
- POST `/cancel`: `{goal_id}`. Stops only that persona goal, preserving survival. A nonmatching goal ID is ignored.
- POST `/chat`: `{text}`. Plain speech only, up to 240 characters, no control/format characters or command prefixes. Session rate limit: one utterance per second.

The body admits only known observations younger than five seconds, health at least eight, overworld, allowed registry items and visible consented follow targets. Obtain counts are 1–64. Goal TTL is at most 120 seconds; local monotonic lease expiry is independent of Python staying alive. An unworkable proposal is rejected before replacement. Typed work is persisted before acknowledgement. The session never restores saved requests or standing dreams in this mode, and incoming game chat becomes a bounded event instead of entering the command/goal interpreter.

Cancellation fences task checks, saves and delayed launches. Existing cooperative task cancellation clears pathfinding, controls, digging and item use. If it has not settled in two seconds, the connection is closed by a watchdog. These bounds require a responsive Node event loop; this is not hard real-time control. Jev's tactical survival arbiter is unchanged. Restart creates a fresh session and rejects old leases. The process's existing SIGINT/SIGTERM remains the operator emergency shutdown.

Completion is verified when an obtain/craft goal reports completion and current inventory actually contains the requested quantity, or when a come goal reports completion and the visible target is observed within three blocks. This means possession, not proof that all items were newly gathered. Follow completion is never asserted; it ends by cancellation/expiry. Accepted, blocked, failed, cancelled and expired events are not proof of successful acquisition.

Run `npm test` for offline admission, fake-session and real loopback transport tests. A sandbox may require permission for the temporary local listener. These tests use no Minecraft server, provider request, public connection or speech service. Matching-version Minecraft gameplay and cancellation during real network actions remain live acceptance work.
